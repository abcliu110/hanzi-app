## (a) 现状一句话诊断

**知识点「库」已经很厚（16 个子模块、约 300 个点、909 道点内练习 + 2137 道选择题），但 50 篇课文本身仍是「原文 / 导读 / 译意 / 重点」四块静态文字：没有逐字对照、没有朗读和断句、没有动画，也没有把篇里的虚词、句式连到知识点上。孩子看得到译文，却看不到「哪个字对应哪个词、语序是怎么调过来的」。**

### 强项
1. 知识点体系完整，字段规范统一（与语法模块同构），而且有出处意识（如注明 18 虚词名单来自考试大纲而不是课标）。
2. 白板引擎成熟：确定性渲染、先猜再揭晓、朗读、可拖进度。模板化以后，写数据就能出动画。
3. 错题和间隔复习已经打通。

### 弱项
1. **篇目页没有交互**：不能点字看释义，没有逐句对齐，没有拼音和停顿，不能朗读。这恰恰是孩子学文言最需要的一层支架。
2. **知识和篇目两张皮**：例如「何陋之有」已经在知识库里作为宾语前置例句出现，但《陋室铭》页面不会提示，也跳不过去。
3. **图示是假图示**：150 个点的 SVG 都是同一种文字框模板。
4. **题型单一**：只有选择题，没有翻译、断句、排序、拖词、句式还原这类「产出型」练习。
5. **寓言 13 篇只有文字**：没有利用「故事—转折—道理」的天然戏剧结构。
6. **白板引擎完全没用在古文上**；`morph` 只停在设计稿里。

## (d) 改进方案（按优先级）

### 数据规范（P0 前置，一次定好）

在 `data/guwen.js` 每篇加以下**可选字段**（旧字段不动，没有就降级显示）：

```js
句: [ // 按句切分，顺序与原文一致
  { 原:'宋人有耕者。', 今:'宋国有个种田的人。',
    停:'宋人/有耕者',                // 朗读停顿（诵读）
    对:[ ['宋人','宋国人'], ['有','有'], ['耕者','种田的人', {法:'换'}] ],
    式:{ k:'定语后置?', note:'暂不标，待核' } // 句式标签，可空
  },
  { 原:'因释其耒而守株，冀复得兔。', 今:'于是他放下农具守着树桩，希望再捡到兔子。',
    停:'因/释其耒/而守株，冀/复得兔',
    对:[ ['因','于是',{类:'虚词',点:'xuci:因'}], ['释','放下'], ['其','他的',{类:'虚词',点:'xuci:其'}],
         ['耒','农具'], ['而','（连接）',{法:'删'}], ['守','守着'], ['株','树桩'],
         ['冀','希望'], ['复','再'], ['得','得到'], ['兔','兔子'] ] }
],
插图: [ {字:'株', svg:'icon_zhu'}, {字:'耒', svg:'icon_lei'} ], // 页边小图（自绘线稿，规范禁 OpenMoji）
wb: 'gw_shouzhu'   // 对应白板场景（可空）
```

- `对` 的第三项 `{类, 点, 法}`：`类` ∈ 实词 / 虚词 / 通假 / 古今异义 / 活用 / 一词多义；`点` 直接用知识库 key（如 `guyin:走`），这样跳转零歧义；`法` ∈ 留 / 换 / 删 / 补 / 调（对应 `fanyi:*`）。
- 现有 `重点` 可以作为 `对` 的种子：先用脚本把 `重点` 里的字在 `原文` 里定位，再人工补全。**内容不编造**：今译词取自现有 `译意`，有疑问的进 §10 待定。
- 工作量：50 篇约 3,500 字，按每篇 30–60 分钟人工校对估算。先做 13 篇寓言和小学课内篇。

### 分镜一（P0-A）：《守株待兔》——寓言白板 + 逐字对译点读

**原文**（`data/guwen.js`）：宋人有耕者。田中有株，兔走触株，折颈而死。因释其耒而守株，冀复得兔。兔不可复得，而身为宋国笑。

**学习目标**：①读懂故事；②抓住 4 个关键字：走（跑，古今异义）、释（放下）、冀（希望）、复（再）；③「为宋国笑」的「为」表被动（知识库 `yufa:被动句` / `为…所…`）；④说出道理。

### 分镜二（P0-B）：句式拆装 `morph`——《陋室铭》「何陋之有」+《曹刿论战》「何以战」

**依据**：知识库已有「何陋之有（有什么简陋的呢；‘之’是宾语前置的标志）（来源：Wikibooks《文言》）」，以及 `yufa` 中「何…之」「倒装句」两个点。两句都在我们 50 篇里，一句用「之」做标志，一句是疑问代词作介词宾语，**一个幕里对比两种宾语前置**。

**学习目标**：①认出「疑问代词（何）作宾语 → 放到前面」；②会还原语序；③知道「之」在这里只是标志，翻译时删掉（翻译法「调」+「删」）。

| 拍 | 时长（估） | 画面 | 旁白（say） | 引擎动作 |
|---|---|---|---|---|
| 0 钩子 | ~8 s | 一扇简陋的木门（线稿），门楣上写「陋室」，下面浮出孔子那句话：**何陋之有？** | 「《陋室铭》最后一句：孔子云，何陋之有？按字面一个个翻：什么、简陋、的、有？读不通。」 | 词块 `何 / 陋 / 之 / 有` 依次落下，每块下面显示「逐字硬译」灰字：什么 / 简陋 / 的 / 有 → 打 ✗（`fix` 的圈错） |
| 1 找枢纽 | ~12 s，含 4 s 想一想 | 四个词块排成一行。「之」被**枢纽圈**（橙色虚线圈）圈住并轻轻跳动 | ask：「这个『之』，能翻成『的』吗？」→ 停 4 s →「不能。它在这里不当『的』讲，只是一个**记号**，告诉你：宾语跑到前面来了。」 | `hub:'之'`；「之」块下方出标签「宾语前置标志」 |
| 2 搬家 | ~12 s，含 4 s 想一想 | 「何陋」两块绑成一个 **chunk**（共用描框），标签「宾语：什么简陋」；「有」块标签「动词」 | ask：「今天说话，宾语该站在动词前面还是后面？」→ 停 4 s →「后面。我们把它搬回去。」 | `chunk:['何','陋']`；chunk 抬起，沿弧线移到「有」右边；原位留**虚线空位框**；「之」淡出（翻译法「删」）。底部公式行：`宾 + 之 + 动  →  动 + 宾` |
| 3 读今译 | ~8 s | 现在一行是：**有 何陋**；右区今译「有什么简陋的呢？」，连线 有→有、何→什么、陋→简陋 | 「有何陋，有什么简陋的呢？孔子的意思是：一点也不简陋。」 | 读完打 ✓；底部「调」「删」两个翻译法标签亮起（链 `fanyi:调`、`fanyi:删`） |
| 4 变式 | ~16 s，含 4 s 想一想 | 换场：《曹刿论战》里曹刿问鲁庄公「**何以战**？」三个词块 | ask：「这一句没有『之』，宾语还前置吗？」→ 停 4 s →「也前置。『何』是疑问代词，当介词『以』的宾语，疑问句里要放到『以』前面。」 | 「何」块打枢纽圈（标签「疑问代词」）；「何」单独抬起，移到「以」右边，留空位；变成 **以何 战**；今译「凭什么作战？」，连线 以→凭、何→什么、战→作战 |
| 5 收口 | ~9 s | 两个公式并排：`何 + 陋 + 之 + 有 → 有 + 何陋` ｜ `何 + 以 + 战 → 以 + 何 + 战` | 「记住：疑问句里，代词『何』作宾语，常常跑到前面；看到『之』夹在中间，也是宾语前置的记号。翻译时，搬回去。」 | `end`：口诀「疑问代词作宾语，先搬回去再翻译」（措辞上线前与知识库「何…之」条目的口诀统一） |

**可选错改示范（L2，`wrongTry`）**：把「何陋之有」翻成「什么简陋的有」，只删了「之」，没调语序 → chunk 抖动（确定性正弦）→ ✗ →「只删不调，还是读不通」→ chunk 回到原位，再走一遍正确搬家。这一拍专门针对孩子最常见的「只删不调」，正是 Ingenium 实验里显著下降的那类词序错误。
