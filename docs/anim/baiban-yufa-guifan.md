## 1. 核心原则

1. **先问「孩子要看到什么变化」**：位置变了、对错分开了、形式变了、指向变了，还是先后变了。答案决定用哪个模板（§3）。
2. **内容和动画分开**：每课只写内容数据，模板负责怎么演，不为每课单独写动画代码。
3. **画面只由时间 t 决定**：任何一帧都可以定格、拖动、截图验收。
4. **先猜再揭晓**：每次揭晓答案前停 4 秒，倒计时圈加「想一想……」。
5. **动必有因**：只有表示变化的东西才动，不加装饰性动画。
6. **保持放慢后的节奏**：不加快。
7. **内容不编造**：语法结论、字源、词源都必须有可靠出处（§8）。

## 4. 内容数据格式

一课是一个 JSON：若干幕，每幕写 `type`（模板名）、`data`（内容）、`cues`（字幕和朗读）。作者只填内容，不写动画代码。

```json
{
  "lesson": "名词",
  "grade": "3-4",
  "speed": 1.0,
  "scenes": [
    {
      "type": "try_fit",
      "title": "怎么认名词",
      "data": {
        "probe": "三个",
        "items": [
          {"word": "书包", "ok": true},
          {"word": "跑", "ok": false}
        ]
      },
      "cues": [
        {"t": 0, "say": "在词前面加上数量词试试。"},
        {"t": 6, "say": "三个书包，能说。", "think": 4}
      ],
      "source": "黄伯荣、廖序东《现代汉语》增订六版"
    }
  ]
}
```

规则：
- 字幕时长按字数自动计算（约 3.5 字/秒，三四年级慢速档），动画自动对齐，不手调秒数。
- `think: 4` 表示揭晓前停 4 秒并显示倒计时圈。
- `speed` 是全课速度系数，三四年级和五六年级共用一份脚本，只改这一个参数。
- 每个事实性结论都要写 `source`。

## 5. 播放器（引擎）

### 5.1 结构
- `render(t)`：根据 t 算出每个元素的状态，没有隐藏状态。
- 进度条可以拖动；拖动时停止朗读，松手后从当前句继续。
- `__seek(t)`：提供给截图验收用。

### 5.2 原语（来自名词样片，已在 `newhanzi/wb/wb-engine.js` 实现为模板动作）
画图形、写字、符号帽（蒙氏符号）、词卡、滑入、淡出、变灰、倒计时圈、箭头、下划线、排一行句子。具体动作名和参数见 `newhanzi/wb/wb-engine.js` 文件头注释。

### 5.3 关键技巧
1. **一笔一笔画出**：路径设 `pathLength=1`，用 `stroke-dashoffset` 从 1 变到 0，多条笔画按顺序接力。
2. **手写字**：用 clipPath 从左往右拉开，揭开时长按字数算。
3. **手绘抖动**：rough.js 换随机种子，每秒换约 6 次。
4. **简单小动画**：身体只画一次，用正弦函数控制位移、轻跳和腿的摆动，换方向时水平翻转。
5. **镜头推进**：白板画大一些，只改 SVG 的 `viewBox` 来平移、放大到要讲的地方。

## 6. 教学技巧

依据 Mayer 多媒体学习原则，结合小学课堂经验：

1. **互动**（最优先）：动画演完后让孩子自己做一遍，拖一拖、点一点、圈一圈。
2. **答错就重播**：选错了，自动跳回讲这个点的那几秒。
3. **分段**：每幕不超过约 1 分钟，只讲一件事。
4. **先示范再放手**：第一个例子完整演，第二个只给提示，第三个让孩子自己做。
5. **最小对比**：只改一个地方，例如的/地/得、句号/问号。
6. **字幕不重复朗读**：朗读整句时，屏幕上只留关键词。
7. **颜色固定含义**：墨黑是正文，橙色 #EF7226 是重点，绿色是对，红色是错，形旁和声旁固定两种颜色，全 App 不变。
8. **固定吉祥物**：同一只小动物贯穿各课。动物身体用简单图形加正弦摆动；需要复杂动作时用姿势库。
9. **动作记忆**：动画里带一个手势，孩子跟着做，适合方位词和动词。
10. **每次不一样**：练习里的物体、位置随机替换，让孩子学的是规则，而不是记住某个画面。
11. **前后呼应**：新课开头用 10 秒回顾上一课的动画帧。
12. **小故事串联**：一课是一个小情节，知识点都藏在情节里。
13. **音效**：画线时有铅笔沙沙声，答对有叮咚声，每个音效几 KB。
14. **减少动画模式**：系统开启 prefers-reduced-motion 时，自动改成静态分步图。

### 6.8 人物（只在必须时使用）
- 不手写小人，不用切件骨骼（v2-jishu §2）。
- 用 AI 一次生成一套共享姿势库（约 12 个：站、走 4 帧、跑、跳、爬、坐、攀、指、藏），离线矢量化为线稿，全部幕共用。
- 每幕体积「几十 KB」只是估计，**未实测**。
- `video2stick.py`（MediaPipe 视频转关节角）只用于做参考，要等有真实的全身侧拍视频后再测试。

## 7. 制作流程

1. **课文 → 脚本**：AI 把课文转成 §4 的 JSON，同时选好模板、写好台词。
2. **人工审内容**：核对每个事实和出处（§8），改掉课文里不准确的说法。
3. **生成**：播放器读取 JSON，自动出动画。
4. **截图验收**：Playwright 在每幕固定关键帧截图，拼成总览图人工检查，同时监听页面报错，要求 0 个错误。
5. **截图回归**：改引擎后自动比对旧截图，防止旧幕被改坏。
6. **一份数据多种输出**：同一份脚本可以出 App 内动画、视频（可选）和打印版分步图。
7. **数据反馈**：只在本机记录孩子在哪一幕暂停、重播、答错最多，用来改动画，不上传。

### 7.1 入库与交付
- 每做完一项（一个语法点）就 commit + push 到 `master`，提交信息写「语法白板：<名称>」，同时更新本文 §11 进度表。
- 提交前必须：`python3 tools/wb/check_wb.py <名称>` 0 错误（每幕若干时间点渲染、无报错、无出框）；`node tools/check_scripts.js` 通过；亲眼看总览截图。
- 不改写历史、不强推、不新建分支；推送前先 `git pull --rebase`。
- 不提交截图、`node_modules`、环境文件。

## 8. 内容准确性

- 语法结论以权威教材为准：黄伯荣、廖序东《现代汉语》（增订六版）、张斌《现代汉语语法十讲》。
- 字源以可靠字书和研究为准（如《说文解字》及其注本、权威字源工具书），不能凭字形猜。
- 名词样片中已经修订的两处（**待用户确认**）：
  1. 原文「名词不能直接作状语」不准确：时间名词、处所名词可以作状语（我们北京见、他明天去）；一般名词作状语只限少数（电话联系、现金支付）。
  2. 「院子里」的「里」按课文自己的定义是方位名词，应戴小三角，不应变灰。
