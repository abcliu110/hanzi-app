# 掌握度模型规格（阶段0 · 地基）

> 三态间隔模型，规则版（非ML）。只定义规格，不动代码。
> 状态：待 Lucas 拍板。拍板后阶段1（效率引擎）方可动代码。

## 1. 目标与范围

- 给每道题（以题目 id 为粒度）定义三种掌握状态：**未学 / 学习中 / 已稳**。
- 状态必须能从**现有 localStorage 账本派生**，不新增存储键，不改现有写入逻辑。
- 老存档（`nhz_wrong`、`nhz_srs`、`nhz_quiz_wrong`）**零丢失**：字段一个不少，语义不变。
- 本规格只覆盖"状态是什么、怎么流转"；"每天推什么题"归阶段1（效率引擎）。

## 2. 现有账本盘点

### 2.1 `nhz_wrong`（统一错题本）

数组，元素结构（`fuxi.js` / `quiz/engine.js` 的 `NHZReview.record` 写入）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 题目唯一键，`hash(q + '\n' + options.join('\n') + '\n' + answer)`，如 `q12345678` |
| `q` | string | 题干 |
| `options` | string[] | 选项 |
| `answer` | string | 正确答案 |
| `解析` | string | 解析（可空） |
| `src` | string | 来源，如 `语法` / `古文` / `quiz` |
| `point` | string | 知识点，如 `把字句` |
| `addedAt` | number | 首次记入时间戳（ms） |

写入点（4处，均调 `NHZReview.record(it, correct)`）：
- `yuwen.js` 语法 bank 答题反馈（2处：bank 批量题、小测题）
- `guwen.html` 古文 bank 答题反馈
- `quiz/engine.js` quiz 答题反馈

写入规则（现有，不改）：
- 答错 → 若 `id` 已在错题本则更新题面（保留原 `addedAt`），否则追加；同时 `nhz_srs[id] = {iv:0, next: 明天}`。
- 答对 → 仅当 `srs[id]` 已存在时推进间隔；否则**不建档**（见 §4 说明）。

### 2.2 `nhz_srs`（复习安排）

对象，`{ [id]: { iv, next } }`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `iv` | number | 间隔档位索引，0–5 |
| `next` | number | 下次复习时间戳（ms） |

间隔表 `IV = [1, 2, 4, 7, 15, 30]`（天），三处 helper 共用同一常量（`fuxi.js`、`quiz/engine.js`，注释要求"保持一致，勿单改一处"）。

变更规则（现有，不改）：
- `record(it, false)`（答错）：`{iv:0, next: now+1天}`
- `record(it, true)`（答对复习项）：`iv = min(iv+1, 5)`，`next = now + IV[iv]天`
- `review(id, true)`（复习页"记得"）：同答对推进
- `review(id, false)`（复习页"忘了"）：`{iv:0, next: now+1天}`
- `clearWrong(id)`（已掌握清除）：同时删除 `nhz_wrong` 条目与 `nhz_srs[id]`

### 2.3 `nhz_quiz_wrong`（quiz 自有错题本，不动）

结构 `{tab: {mode: [q, ...]}}`，`quiz/engine.js` 的 `wbAdd/wbRemove` 维护。**不纳入三态模型**，保留原样（注释明确"不碰 quiz 自有错题本的逻辑"）。

### 2.4 已废弃旧键（不迁移）

`xzq_learned` / `hz_wrong` / `hz_srs` 仅在注释中提及（"不用旧 app 的键"），代码无读写。**不做迁移**，规格不覆盖。

## 3. 三态定义

三态是**派生视图**，不是新增存储。定义如下（`id` 为题目键）：

```
state(id):
  srs = load('nhz_srs', {})
  if id ∉ srs        → 未学
  else if srs[id].iv ≥ 5 → 已稳      # IV.length - 1
  else               → 学习中
```

设计说明：
- **为什么是派生而非新增字段**：现有两键已完备表达状态机（`iv` 即进度，`next` 即到期，错题本即题面库）。新增 `state` 字段会引入"字段与 iv 不一致"的第二真相源；派生保证单一真相源。
- **为什么"未学答对不建档"**：SRS 的职责是安排**薄弱点**复习，不是全量学习档案。全对的新题不需要复习计划，建档只会膨胀存储。这是现有行为，本规格予以确认（不是疏漏）。
- **`已稳`的含义**：连续 5 次到期复习答对（1→2→4→7→15→30 天），累计跨度约 57 天。注意"连续"隐含"按时"——只有 `next` 到期才会出现在复习页，答对即推进，所以 iv 的每次 +1 都对应一次按时答对。

## 4. 流转规则（事件矩阵）

| 当前态 | 事件 | 新态 | 存储变更 |
|---|---|---|---|
| 未学 | 新题答错 | 学习中 | `nhz_wrong` 追加/更新；`srs[id]={iv:0,next:+1天}` |
| 未学 | 新题答对 | 未学 | 无变更 |
| 学习中 | 到期复习答对 / 点"记得" | 学习中（iv<5）或已稳（iv 到 5） | `iv=min(iv+1,5)`，`next=+IV[iv]天` |
| 学习中 | 到期复习答错 / 点"忘了" | 学习中 | `iv=0`，`next=+1天`；错题本更新 |
| 学习中 | 非复习场景答对（如 bank 刷题） | 学习中/已稳 | 同"答对"推进（现有 `record` 行为） |
| 学习中 | 非复习场景答错 | 学习中 | 同"答错"回退（现有 `record` 行为） |
| 已稳 | 到期复习答对 | 已稳 | `iv` 保持 5，`next=+30天` |
| 已稳 | 答错（任何场景） | 学习中 | `iv=0`，`next=+1天`；错题本更新/追加 |
| 学习中/已稳 | 用户"已掌握清除" | 未学 | 删除 `srs[id]` 与错题本条目 |
| 未学 | 用户"已掌握清除" | 未学 | 无操作（`clearWrong` 对不存在的 id 是空操作） |

边界说明：
- **逾期未复习**：`next < now` 的题仍保持原态（学习中/已稳），只是"到期"。阶段1的队列按"逾期时长"排序优先。
- **题面变更导致 id 变化**：`idOf` 依赖题干+选项+答案的 hash。若数据更新改了题面，旧 `id` 成为孤儿记录（srs/wrong 中残留但无题可对）。本规格不处理（现有行为）；建议阶段1实现"孤儿清理"时再定（需 Lucas 拍板是否自动删）。

## 5. 间隔算法

```
IV = [1, 2, 4, 7, 15, 30]  # 天
推进：iv ← min(iv + 1, 5)；next ← now + IV[iv] × 86400000
回退：iv ← 0；next ← now + 1 × 86400000
```

- 与现有 `fuxi.js` / `quiz/engine.js` 的 `NHZReview` 实现**逐行一致**（模拟脚本已验证，见 §7）。
- 三处 helper 的 `IV` 常量与 `record/review/clearWrong` 逻辑必须保持同步（现有注释要求，规格重申）。
- 本规格**不引入** FSRS/SM-2 的难度系数（easiness factor）——规则版有意保持简单；若将来要上，在此另起规格。

## 6. 老存档字段映射表（零丢失证明）

| 老位置 | 字段 | 新模型中的角色 | 处理 |
|---|---|---|---|
| `nhz_wrong[i]` | `id` | 三态键（关联 srs） | 保留，hash 算法不变 |
| `nhz_wrong[i]` | `q` / `options` / `answer` | 题面库（复习页渲染用） | 保留 |
| `nhz_wrong[i]` | `解析` | 题面库 | 保留 |
| `nhz_wrong[i]` | `src` / `point` | 题面库（来源标注） | 保留 |
| `nhz_wrong[i]` | `addedAt` | 题面库（首次记入时间） | 保留，更新时不覆盖 |
| `nhz_srs[id]` | `iv` | 派生态的核心输入 | 保留 |
| `nhz_srs[id]` | `next` | 到期判断输入 | 保留 |
| `nhz_quiz_wrong` | 全部 | quiz 自有错题本 | **保留不动**，不纳入三态 |
| `xzq_learned` / `hz_wrong` / `hz_srs` | — | 已废弃 | 不迁移 |

校验方式：模拟脚本（`/tmp/srs_sim.js`，见 §7）跑完 60 天后逐字段断言，输出 `PASS：所有老字段完整保留，无丢失`。

脚本：`/tmp/srs_sim.js`（`node srs_sim.js` 可复跑）。移植 `fuxi.js` 的 `record/review/clearWrong` 逻辑（逐行等价），虚拟时钟推进 60 天，三道样例题（真实字段结构：`q/options/answer/解析/src/point`）。

D3  Q1记得       Q1=学习中(iv=2,next=D7)
D7  Q1记得       Q1=学习中(iv=3,next=D14)
D14 Q1答错回退   Q1=学习中(iv=0,next=D15)
D28 Q1记得       Q1=学习中(iv=4,next=D43)
D43 Q1记得→已稳  Q1=已稳(iv=5,next=D73)

覆盖的流转路径：未学→学习中、学习中→已稳、已稳→学习中（回退）、→未学（清除）、未学答对不建档、逾期补复习。全部符合 §4 矩阵。

## 8. 与阶段1（效率引擎）的接口

阶段1实现今日队列时，按以下**只读查询**消费三态（函数签名，具体实现归阶段1）：

```
dueItems(now):  [{id, iv, next}]   # srs 中 next <= now 的，按 (now - next) 降序（将忘/已忘优先）
wrongItems():   [{id, ...}]        # nhz_wrong 中 iv=0 或不在 srs 的（错题回炉）
stateOf(id):    '未学' | '学习中' | '已稳'   # §3 定义
```

阶段1的"三段配比"（到期复习→错题回炉→新学配额）直接用这三个查询拼装。本规格不规定配比数字，归阶段1规格。
