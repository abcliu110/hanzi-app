## 1. 目标和非目标

### 1.1 目标
1. **让语法「看得见地变化」**：补上现有画面没有的三种动作——词块位移（变换）、层层套装（层次）、关系连线（配价、指向）。
2. **符号不打架**：词类、成分、对错三层各有一个视觉通道，颜色互不共用，并由工具强制检查。
3. **深内容有地方放、讲得浅**：每项按 L1 直觉 / L2 规则 / L3 学理分层；播放器提供浅、中、深三档；L3 写明出处。
4. **一个模板升级，几十项受益**：新增 `trunk`、`morph`、`nest`（P0/P1）和 `valence`（P1）、回练幕，复用面覆盖成分、句式、短语、病句、复句。
5. **对现有 99 项向后兼容**：引擎改动不得让未改的场景出现任何意外变化（用渲染哈希基线证明）。

### 1.2 非目标
- 不支持手机竖屏（<768）；不为手机做单独布局。
- 不做配音 MP3、不引入 GSAP / esbuild（规范 §2 不变）。
- 不手写 SVG 小人、不做骨骼动画（规范 §0、§6.8 不变）；「动词伸手」只画线，是否加眼睛等拟人元素列为待确认（§10 Q8）。
- 本期不改 `data.js` 的语法正文；正文疑点按规范 §0.1 第 8 条记到 §10，不擅改。
- 不把 `games/yufa/` 的 4 个独立原型并入白板（回练幕先做纯观看版，见 §5.5）。
- 逻辑（15）、阅读（14）、写作（16）三区不在本设计范围（口径见 §10 Q15）。
- 不清理 `yuwen.js` 中旧「看图说话 / 动手试试」渲染分支（约 L312–329，数据已删）；可另开小提交。

512 幕中只有 **11 幕**在句子里画了箭头（`mark.arrows`，共 12 支，`兼语句` 一幕 2 支）：宾语、代词、定语、动词、副词、兼语句、介词、量词、名词、比喻、形容词。语义指向、配价、施受关系基本没有可视化。（`link` 31 幕、`rel` 6 幕自带的分句间 / 两块间箭头不计在内。）

### 2.3 词块从不移动
- `slide()`（`wb-engine.js:93–95`）只在两处使用：`test` 的试探词卡飞入（`:230`）、`link` 的关联词卡飞入（`:367–368`）。
- `sentence()`（`:133`）返回的词块从未被平移过。

### 2.4 状态会互相覆盖（潜在缺陷）
`recolor()`（`wb-engine.js:92`）在 `t < t0` 时把颜色重置为初始色。同一词块注册两次 `recolor` 时，后注册者会在自己 `t0` 之前把前一次的颜色抹掉。当前 99 项没有触发（已逐幕检查 `mark` 的 `m` 与 `gray` 无交集），但 `trunk`「先变灰、再恢复」必然触发，必须先改成属性时间线（§7 E1）。

### 2.5 结构单一、片头片尾占比高

### 2.6 没有难度层，也没有出处
- `data.js` 语法 99 项**全部**有「深讲」字段，但白板没有任何 L3 幕可承接。
- 规范 §4 要求每个事实结论写 `source`，而 99 个场景文件里**0 个**有 `source` / `src` 字段。

### 2.7 其他
- 白板唯一的交互是点画布暂停 / 播放（`wb-engine.js:510`），没有回练。
- 随机种子按幕的**位置**取（`wb-engine.js:451`：`20261104 + idx * 1000`）。一旦按难度过滤掉前面的幕，后面每幕的手绘抖动都会变——必须改成按原始序号取种子（§7.2）。

## 3. 符号三层体系

### 3.1 分层与位置

```
            施事 · 受事 标签（上方第 2 行，文字标签）
            ▲ ● ▲ ◗                 ← 词类层：形状 + 颜色，画在字的上方
         调皮的 小猫 捉住了 老鼠      ← 句子本身（墨色）
         （    ）═══ ‖ ＿＿＿ ～～～    ← 成分层：线型，画在字的下方
            定+主   ‖  谓   宾        ← 公式行（可选，§5.1）
```

| 层 | 通道 | 位置 | 颜色 | 何时出现 |
|---|---|---|---|---|
| 词类 | **形状 + 颜色**（蒙氏） | 字的上方，底边距字顶 18px | 词类色（8 + 1 种） | 讲词类、依句辨品时 |
| 成分 | **线型**（只用一种成分墨） | 字的下方，距基线 16–30px | 成分墨 `#4f5d7a` | 讲成分、抽骨架、病句时 |
| 对错 | **只用 ✓ 和 ✗** | 句末右侧，或被判的块上方 | 对 `#0f8c8c`、错 `#8f1d3f` | 判断时 |

规则：
1. 一种颜色只属于一层；跨层 ΔE ≥ 20（工具强制，§8）。
2. 对错层只有 ✓ ✗ 两个符号以及紧跟它们的一句判词；**不许**把词或成分染成对错色（现状 `binyu.js` 的宾语绿即属此类）。
3. 同一幕默认只「点亮」一层；另一层若需同屏，降为 35% 不透明度（待确认 §10 Q2）。
4. 「错的部分」用错色椭圆圈 + ✗ 同时出现；只画圈不打 ✗ 视为违规（区别于 §6.4 的枢纽圈）。

### 3.2 成分线型（中学通用划线符号）

| 成分 | 符号 | 画法（rough，确定性种子） | 原语 `role(kind)` 的 kind |
|---|---|---|---|
| 主语 | 双横线 ═ | 两条平行线，间距 5px | `zhu` |
| 谓语 | 单横线 ＿ | 一条线 | `wei` |
| 宾语 | 波浪线 ～ | 正弦路径，波长 = 字号 × 0.5 | `bin` |
| 定语 | （ ） | 字两侧的圆括号 | `ding` |
| 状语 | 〔 〕 | 字两侧的六角括号 | `zhuang` |
| 补语 | 〈 〉 | 字两侧的尖括号 | `bu` |
| 主谓分界 | ‖ | 主语与谓语之间的双竖线 | `bar` |

- 默认方案取「主双横、谓单横、宾波浪」，这是调研一 #9 所列中学通行用法；网上也有谓语、宾语互换的说法（调研一 §7、调研二 §2），**待确认**（§10 Q1）。
- 括号类成分「包住」词块，词块移动时括号跟着移动（括号挂在块上，不挂在坐标上）。

### 3.3 新色板

**词类层**（沿用蒙氏与规范 §11.3，不改）：名词 `#26221c` ▲、形容词 `#274b8f` ▲、代词 `#7b4ba8` 细高▲、动词 `#c22f2f` ●、副词 `#e07b24` 小●、介词 `#3d8a4f` ◗、连词 `#d96a9b` ▬、叹词 `#c9a227` !；数词、量词、助词、语气词用灰框标签 `#6b7566`。

**成分层**：成分墨 `#4f5d7a`（灰蓝），只此一色，靠线型区分成分。

**对错层**：对 `#0f8c8c`（青绿，替换原 `#3f8e6b`）；错 `#8f1d3f`（深玫红，替换原 `#b85a52`）。

**叙事层**（不属于三层，用于正文、提示、强调，同样不得与三层撞色）：墨 `#2c3328`、灰 `#a3aa9c`、强调 `#a8642f`（替换原 `#c46a2b`，每幕仍只用一种强调色）、对照 `#8c6d3a`（替换原 `BLUE #4a7a8c`，原色与成分墨 ΔE 仅 15）。

校验结果（ΔE76，均 ≥ 20）：对 vs 介词 34.3；错 vs 动词 30.7；错 vs 连词 31.4；强调 vs 副词 25.7；成分墨 vs 形容词 26.0；对 vs 成分墨 36.1；对照 vs 叹词 37.2。唯一例外：名词 ▲ `#26221c` 与正文墨 `#2c3328`（ΔE 9.3）——名词符号是**实心三角**，正文是字，形状不同；正文墨不属于三层，豁免并在工具里写死这一条豁免。

色板集中定义在引擎 `PAL` 常量，场景只写语义键（`cls:'verb'`、`role:'bin'`、`tone:'acc'`），不许写色值（§8 R1）。

### 3.4 施事、受事：上方文字标签
- 施事、受事、话题、本体、喻体等**语义角色**，一律用词块上方第 2 行的**文字标签**：叙事墨色小字 + 虚线小框，如「动手的」「被动手的」「说的是什么」。
- **禁止**借用成分线型（避免调研二 §0.5 指出的撞车：被字句里主语恰恰是受事）。**禁止**借用词类色（现状 `gj_huati.js:9`、`gj_jianyu.js:6` 用动词红标施事）。
- L3 需要「位置 vs 角色」对照时用双层标注：下方是成分线（位置：主语），上方是标签（角色：被动手的）。

### 4.4 播放器三档
- 控制条新增「浅 / 中 / 深」分段按钮：浅 = 只放 lv≤1；中 = lv≤2；深 = 全部。
- 默认「中」（待确认 §10 Q16）；选择存 `localStorage('nhz_wb_lv')`（try/catch，与现有 `nhz_wb_mute` 同法）。
- 幕标签按钮、进度条、时长都只算过滤后的幕。
- 按钮高度 ≥ 44px（与现有控件一致）。

### 4.5 L3 用反直觉的最小对比开场
每个 L3 幕的第一拍是一对只差一处、结果却相反的句子，先停 4 秒「想一想」，再给学理解释。所有例句自编，例：
- 把字句：「我把杯子打碎了 ✓ / 我把那首歌听见了 ✗」——为什么第二句不行？（听见没有让歌「变了样」→ 处置）
- 变换：「在本子上画画 → 把画画在本子上 ✓ / 在操场上跑步 → 把步跑在操场上 ✗」——看着一样，其实不一样。
- 程度补语：「小狗累坏了 / 杯子摔坏了」——两个「坏了」意思一样吗？
- 层次：「三个班的同学」——是三个班，还是三个同学？

## 5. 新模板

通用约定：新模板全部遵守规范 §1（先猜再揭晓、动必有因）、§0.1 第 7 条（3.5 字/秒、揭晓前停 4 秒）；每幕 ≤ 约 60 秒，超过就拆幕。

### 5.1 `trunk` 抽骨架（双向：先生长，再修剪）

**用途**：讲清「句子 = 骨架 + 枝叶」。生长 = 扩句，修剪 = 缩句；修剪靠路标「的、地、得」；否定词、数量词、关键定语受保护，不能剪。

**幕结构**（一幕或拆成生长 / 修剪两幕）：
1. 骨架出场：3–4 个字（「小猫捉老鼠」），画成分线；句下公式行写「谁 + 干什么 + 什么」（L1 儿童名）或「主 ‖ 谓 + 宾」（L2）。
2. 生长若干拍：每拍问一个问题（「哪只小猫？」）→ 想一想 → 新枝叶从上方落入，右边的词块平移让位，括号类成分线包住新块，**公式行同步多出一格**（「定 +」）。
3. 读完整长句。
4. 修剪：「的、地、得」路标依次闪烁（枢纽圈，§6.4）→ 路标前的枝叶下沉并淡出（或 `strike:1` 时打删除线保留可读）→ 骨架词块向中间合拢 → 公式行同步缩回。
5. 保护：被保护的词块戴上「不能剪」小标签（叙事强调色虚线框），试剪时弹回并演示后果（见示例 2），收尾读骨架。

**数据格式示例**：
```js
{ k:'trunk', lv:2, tab:'长出来，再剪回去', mode:'grow+prune',
  core:['小猫','捉','老鼠'], role:['zhu','wei','bin'],
  grow:[
    { q:'哪只小猫？', ins:['胖胖','的'], before:0, role:'ding' },
    { q:'怎么捉的？', ins:['悄悄','地'], before:1, role:'zhuang' },
    { q:'捉到没有？', ins:['住了'], after:1, role:'bu' } ],
  prune:{ cue:['的','地','得'], strike:0 },
  formula:true, ask:'哪几个字是骨头？' }

// 保护示例：试剪会出错的词
{ k:'trunk', lv:2, tab:'这些不能剪', mode:'prune',
  s:['弟弟','不','喜欢','吃','香菜'], role:['zhu','zhuang','wei','wei','bin'],
  keep:[{ i:1, why:'neg' }],
  tryCut:{ i:1, show:'弟弟喜欢吃香菜', verdict:false, say:'剪掉“不”，意思反了。' } }
```
- `keep.why` 取 `neg`（否定）/ `num`（数量）/ `key`（关键定语）。另两个自编保护例：「三个同学没交作业」剪掉「三个」变成全体；「过期的牛奶不能喝」剪掉「过期的」意思错。
- 语法：不写坐标；引擎根据词块序列自动排版，每一步的位置都在构建时算好。

**引擎新增原语**：属性时间线（E1）、词块可移动 `move` 与自动让位 `reflow`（E2）、成分线 `role`（E7）、公式行 `formula`（E5）、删除线 / 下沉 `strike` / `sink`（E11）、枢纽圈 `hub`（E4）、保护标签 `guard`（E4 的变体）。

**适用语法项**：单句成分 7 项（主语、谓语、宾语、定语、状语、补语、趋向补语引申义）；病句中先抽主干再查的约 12 项（搭配不当、主谓 / 动宾搭配不当、成分残缺或赘余、主语 / 谓语 / 宾语残缺、重复啰嗦、否定失当等）；的 / 地 / 得（路标）。

### 5.2 `morph` 变魔术（变换）

**用途**：演示句式之间的变换，以及「能不能变」作为判断工具。名词短语**整块**移动（定语跟着走），原位留下虚线空位；先把枢纽词「把 / 被」圈出来；变换失败就打 ✗。

**幕结构**：
1. 读原句；名词短语块轻微描框（叙事灰），让孩子看到「这是一整块」。
2. 圈出枢纽词「把」（枢纽圈）。
3. 想一想：「变成被字句会怎样？」
4. 块抬起 → 沿弧线移到新位置；原位出现虚线空位框（可标 ∅）。
5. 新枢纽「被」从上方落入，旧枢纽「把」淡出；空位框收起。
6. 读新句 → ✓。
7. 失败分支：块移动后抖动（确定性正弦），打 ✗，旁白说原因；块回到原位。
8. 可选「前后两格状态图」（§6.3）放在句子下方，解释「处置 = 状态改变」。
9. 可选「错改示范」：只搬了「树林」、丢下「茂密的」→ ✗，高亮被丢下的块（来自调研二 #15 的手法，例句自编）。

**数据格式示例**：
```js
{ k:'morph', lv:2, tab:'把字句变被字句',
  from:[ {id:'A', w:['茂密的','树林']}, {id:'h1', w:['把'], hub:1},
         {id:'B', w:['太阳']}, {id:'V', w:['遮住了']} ],
  to:  [ 'B', {id:'h2', w:['被'], hub:1, enter:'drop'}, 'A', 'V' ],
  gap:true, ok:true,
  wrongTry:{ to:['B','被','树林','V'], drop:['茂密的'], say:'“茂密的”丢了。' },
  state:[ {t:'太阳亮着'}, {t:'太阳被挡住'} ],
  ask:'变成“被”字句，谁搬到前面？' }

// 变换失败（L3，变换作为判断工具；例句自编）
{ k:'morph', lv:3, tab:'能变吗', src:'（方法出处，制作时核对）',
  from:[ {id:'P', w:['在','操场','上']}, {id:'V', w:['跑']}, {id:'O', w:['步']} ],
  to:  [ {w:['把'], hub:1, enter:'drop'}, 'O', 'V', 'P' ],
  ok:false, say:'“把步跑在操场上”不能说：这一句和“在本子上画画”看着一样，其实不一样。' }
```

**引擎新增原语**：块 `chunk`（把若干词块绑成一个可移动单元，括号成分线挂在块上）、`move`（直线 / 弧线，多段关键帧）、虚线空位 `gap`（E3）、枢纽圈 `hub`（E4）、落入 `drop`、确定性抖动 `shake`（E12）、状态双格 `state2`（E13）。

**适用语法项**：高级句式 10 项（把字句、被字句、存现句、是…的句、比较句、双重否定、歧义句、兼语句、话题句、给字被动）；病句「语序不当」「定语语序不当」（调序）；虚词「把 / 被」；关联词位置规则（P2，§10 Q11）。

### 5.3 `nest` 套盒子（层次）

**用途**：讲短语和句子「一层层装起来」。L1 用盒子（自底向上画圆角框）；L3 用句子下方的台阶线（一层一行往下切分，标结构名，与教材 / 考研画法一致）。歧义：一句话配两幅图，两种装法各点亮一张情境卡。

**幕结构**：
- box（L1/L2）：读短语 → 想一想「先装哪两个？」→ 最内层框画出 + 标签（L1「谁+怎样」/ L2「主谓」）→ 外一层 → … → 最外框 → 读一遍。
- stair（L3）：句子在上；第 1 行台阶线一分为二并标结构名 → 第 2 行在各段内再切 → … 到词为止（「从左到右，逐层切分；一分为二，到词为止」是通行要领，旁白用自己的话说）。
- 歧义：同一句分左右两栏（或上下两行）各画一种装法；每栏上方一张情境卡（文字 + 线条图标）；切换到哪种装法，就点亮哪张卡。

**数据格式示例**：
```js
// 树的写法：[结构键, 左, 右]，叶子是词块下标
{ k:'nest', lv:1, style:'box', tab:'一层层装',
  s:['妈妈','买','的','新','书包'],
  tree:['pz', ['de', ['zw',0,1], 2], ['pz',3,4]],
  ask:'先装哪两个？' }

{ k:'nest', lv:3, style:'stair', tab:'两种装法', src:'（层次分析出处，制作时核对）',
  s:['表扬','弟弟','的','姐姐'],
  reads:[
    { tree:['pz', ['de', ['db',0,1], 2], 3], pic:{ icon:'user-star', t:'姐姐表扬了弟弟（说的是姐姐）' } },
    { tree:['db', 0, ['pz', ['de',1,2], 3]], pic:{ icon:'thumb-up', t:'要表扬的是姐姐（说的是一件事）' } } ],
  ask:'是哪个姐姐，还是去表扬谁？' }
```

**引擎新增原语**：嵌套框 `nestBox`（复用 `box`，按树深度自动内缩）、台阶线 `stair`（E6）、情境卡 `pic`（文字 + 线条图标，图标来源待确认 §10 Q22）、卡片点亮 / 变灰（E1 时间线）。

**适用语法项**：短语结构 5 项（并列式、偏正式、主谓式、动宾式、补充式）；定语（多层定语排序为什么是这个顺序）；歧义句；复句多重关系（L3，后期）。

### 5.4 `valence` 动词伸手（P1）

**用途**：「动词有几只手、要抓几个名词」，统一解释成分残缺、双宾、兼语、「的」字结构歧义。

**幕结构**：动词红圆（词类符号）出现 → 想一想「它要几只手？」→ 逐只伸出手（从符号画到名词块的带钩弧线）→ 手空着时画虚线并摇晃 → 补上名词，虚线变实线 → 读句子。L3：「门口站着一位老师」——抓住的不一定站在前面。

**数据格式示例**：
```js
{ k:'valence', lv:2, tab:'动词的手',
  rows:[ { s:['下雨','了'], v:0, args:[], say:'下雨，不用抓谁。' },
         { s:['弟弟','游泳'], v:1, args:[0] },
         { s:['我','喜欢','画画'], v:1, args:[0,2] },
         { s:['奶奶','给','我','一个','苹果'], v:1, args:[0,2,4] } ],
  empty:{ s:['奶奶','给','我'], v:1, args:[0,2], miss:1, say:'给什么？有一只手空着。' } }
```
**引擎新增原语**：伸手 `hand`（`arrow` 的变体：端点为钩，可虚线、可摇晃），空位 `gap`（与 `morph` 共用）。
**适用语法项**：动词、宾语、兼语句、成分残缺类病句（主语 / 谓语 / 宾语残缺）、把字句 L3、「的」字结构歧义（L3）。是否允许给红圆加眼睛等拟人化：待确认（§10 Q8），默认只画线。

### 5.5 回练幕 `review`：「这位同学改对了吗？」（先做纯观看版）

**用途**：在不加交互的前提下做回练：展示一个典型错答，孩子先判断，再揭晓。

**幕结构**：出题（原句 + 要求，如「改成被字句」）→ 出现手写风格的「同学的答案」卡 → 想一想 4 秒「这位同学改对了吗？」→ ✓ 或 ✗ → 若 ✗，用错色圈出问题处（丢的、多的、换错的）→ 写出正确答案 → 一句话说规则。

**数据格式示例**：
```js
{ k:'review', lv:2, tab:'改对了吗',
  task:'把“茂密的树林把太阳遮住了”改成被字句',
  answer:'太阳被树林遮住了', ok:false,
  diff:{ miss:'茂密的' },
  good:'太阳被茂密的树林遮住了', rule:'修饰的词要跟着名词一起搬。' }
```
**引擎新增原语**：无新原语，复用 `card`、`check` / `cross`、`ring`（错色）、`diff`（按字符串定位遗漏 / 多余片段，在构建时算好位置）。
**后续**：交互版 `k:'try'`（播放器在该拍暂停等待点击，结果只决定跳转目标 t，不破坏画面 = t 的纯函数）是否进入白板，待确认（§10 Q7）。

## 6. 叙事手法

只借手法，例句全部自编；每种手法写明适用范围和约束。

### 6.1 荒诞错句开场
第一拍出一个把规则用反了的句子，配一张简单的荒诞情境卡（文字 + 线条图标，不画人物），停 4 秒「哪里怪？」，再引出规则。例（自编）：「我被作业写完了」「苹果被小明啃了一口」→ 先怪后对。
约束：错句必须在**同一幕**内纠正并打 ✗；错句不得出现在 `title` / `end`；工具检查「有错句标记的幕必须同时有改正」（§8 R9）。是否允许：待确认（§10 Q9），默认允许。

### 6.2 仿造同结构短句测病
长病句先压成结构泡泡（如「通过 + X，使 + Y」），旁边用**同一结构**造一个 6–8 字的短句，短句的毛病一眼可见（缺主语），再回到长句改正。适用：成分残缺、句式杂糅类病句。短句全部自编（§10 Q12）。可作为后期模板 `mirror`，第 1–3 期不做。

### 6.3 前后两格状态图
句子下方两小格：动作前 → 动作后（「杯子好好的 → 杯子碎了」）。用于把字句「处置」、结果补语、被字句的「受影响」。反例：第二格与第一格一模一样（「我把那首歌听见了」）→ 打 ✗。格子内容只用文字 + 线条图标。

### 6.4 枢纽词统一圈出
把、被、关联词、的 / 地 / 得等「枢纽」一律先用**枢纽圈**（叙事强调色实线椭圆，不带 ✗）圈出，再发生其他动作；枢纽词**不画成分线**。与「错误圈」（错色椭圆 + ✗）严格区分（§3.1 规则 4）。

### 6.5 「词性是身份，成分是岗位」
同一个词卡（如「学习」）先后放进两个句框：「学习 ‖ 很重要」（当主语）和「我 ‖ 学习」（当谓语）。上方的词类符号（身份）不变，下方的成分线（岗位）变了。这一幕同时演示 §3 三层体系为什么分上下：上面是身份，下面是岗位。适用：词类总述、兼类、主语 / 谓语。

### 7.2 怎样保证确定性渲染
1. **画面只由 t 决定**：所有动画状态由关键帧时间线求值（E1），没有隐藏状态；`Math.random`、`Date`、`performance.now` 只允许出现在播放器计时（推进 t）里，不得进入绘制（工具静态检查）。
2. **排版在构建时算完**：`reflow`、`nest`、`stair`、`diff` 的坐标都用现有 `textW()` 估宽算出（不调用 `getBBox`），与字体是否加载无关，所以同一数据在任何机器上坐标一致。
3. **种子稳定**：每幕种子 = `20261104 + 原始序号 × 1000`（原始序号 = 该幕在 `scenes` 数组里的位置，与档位过滤无关）；新模板在幕内按固定顺序消耗种子。
4. **不在旧路径上插入新的 rough 调用**：旧模板的 `R()` 调用顺序不变，种子序列不变，手绘抖动不变。
5. **抖动与摇晃**用确定性正弦（E12），不换随机种子。
6. **验收**：`check_wb.py` 已有「同一 t 渲染两次 SVG 一致」；新增「档位切换前后，同一幕同一 t 的 SVG 一致」。

4. 字段兼容：缺 `lv` = 1；缺 `src` 只在 lv=3 时报错；旧 `col` 色值兼容期内照常渲染（映射到语义键）并报警告；未知字段忽略。
